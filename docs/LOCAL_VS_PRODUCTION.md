# Local Development vs Production Deployment

Quick reference showing key differences between running locally and in production.

---

## Architecture Comparison

### Local Development
```
┌─────────────────┐
│  Your Computer  │
├─────────────────┤
│ Frontend:3001   │ ← React dev server
│ Backend:3000    │ ← Node/Express
│ MySQL:3306      │ ← Local MySQL
└─────────────────┘
        ↓
  Stripe CLI
        ↓
    Stripe.com
```

### Production Deployment
```
┌──────────────┐      ┌──────────────┐      ┌──────────────┐
│   Vercel     │      │   Railway    │      │   Railway    │
│  (Frontend)  │ ←──→ │  (Backend)   │ ←──→ │   (MySQL)    │
│ React Build  │      │ Node/Express │      │  Database    │
└──────────────┘      └──────────────┘      └──────────────┘
                              ↑
                      Direct webhook
                              ↓
                         Stripe.com
```

## Webhook Setup Comparison

### Local Development

**How it works:**
```
Stripe.com → Stripe CLI (running on your computer) → localhost:3000
```

**Setup:**
```bash
# Terminal 1: Start backend
cd backend && npm start

# Terminal 2: Start Stripe CLI
stripe login
stripe listen --forward-to localhost:3000/api/webhooks/webhook
```

**Webhook Secret:**
- Generated by Stripe CLI
- Changes every time you restart CLI
- Shown in terminal output: `whsec_xxxxx`
- Copy to `backend/.env`

**Limitations:**
- ❌ Only works when your computer is on
- ❌ Only works when Stripe CLI is running
- ❌ Can't receive webhooks from real Stripe events
- ❌ Can't share with others

**Good for:**
- ✅ Development
- ✅ Testing webhook handlers
- ✅ Debugging

---

### Production Deployment

**How it works:**
```
Stripe.com → Your Railway Backend (public HTTPS URL)
```

**Setup:**
1. Deploy backend to Railway
2. Get public URL: `https://your-app.up.railway.app`
3. Go to Stripe Dashboard → Webhooks
4. Add endpoint: `https://your-app.up.railway.app/api/webhooks/webhook`
5. Select events to listen for
6. Copy webhook signing secret
7. Add to Railway environment variables
8. Redeploy backend

**Webhook Secret:**
- Generated by Stripe Dashboard
- Permanent (doesn't change)
- Specific to this endpoint
- Copy to Railway env vars

**Advantages:**
- ✅ Works 24/7 (always online)
- ✅ Receives real Stripe events
- ✅ Can share URL with anyone
- ✅ No need to run Stripe CLI
- ✅ Production-ready

**Good for:**
- ✅ Live demo
- ✅ Showing to recruiters
- ✅ Real customers
- ✅ Portfolio projects

## Environment Variables Comparison

### Local (.env file)

```env
# Frontend (receipt-scanner/.env)
REACT_APP_API_URL=http://localhost:3000

# Backend (backend/.env)
DB_HOST=localhost
DB_USER=root
DB_PASSWORD=your-local-password
DB_NAME=smartslip
DB_PORT=3306

STRIPE_SECRET_KEY=sk_test_xxxxx
STRIPE_WEBHOOK_SECRET=whsec_aafec132d36ee449fd11ec309fa1641776add593ce919e107cb4c9e10076c8a2

JWT_SECRET=your-local-secret
OPENAI_API_KEY=sk-proj-xxxxx
```

**How to use:**
- Create `.env` file in project root
- Never commit to GitHub
- Must restart server when changed

---

### Production (Platform Dashboard)

```env
# Frontend (Vercel Dashboard)
REACT_APP_API_URL=https://smartslip-backend.up.railway.app

# Backend (Railway Dashboard)
DB_HOST=containers-us-west-xxx.railway.app
DB_USER=root
DB_PASSWORD=railway-generated-password
DB_NAME=railway
DB_PORT=7896

STRIPE_SECRET_KEY=sk_test_xxxxx
STRIPE_WEBHOOK_SECRET=whsec_different-from-local-secret

JWT_SECRET=production-secret-minimum-32-chars
OPENAI_API_KEY=sk-proj-xxxxx
FRONTEND_URL=https://smartslip.vercel.app
```

**How to use:**
- Set in Railway/Vercel dashboard
- Not stored in code
- Changes take effect on next deployment
- Separate for each environment (dev/staging/prod)

## Development Workflow Comparison

### Local Development

**Daily workflow:**
```bash
# 1. Start MySQL
# (automatically starts on system boot)

# 2. Start Backend
cd backend
npm start

# 3. Start Frontend (new terminal)
cd receipt-scanner
npm start

# 4. Start Stripe CLI (new terminal)
stripe listen --forward-to localhost:3000/api/webhooks/webhook

# Now you can develop and test
```

**Making changes:**
1. Edit code
2. Backend: Restart server
3. Frontend: Auto-reloads
4. Test locally

**Pros:**
- ✅ Fast iteration
- ✅ Easy debugging
- ✅ Full control
- ✅ Works offline (except Stripe/APIs)

**Cons:**
- ❌ Need all services running
- ❌ Can't share with others easily
- ❌ Environment differences from production

---

### Production Workflow

**Deployment workflow:**
```bash
# 1. Make changes locally
git add .
git commit -m "Add new feature"

# 2. Push to GitHub
git push origin main

# 3. Automatic deployment
# - Vercel auto-deploys frontend
# - Railway auto-deploys backend

# 4. Test production site
# Visit: https://smartslip.vercel.app
```

**Making changes:**
1. Edit code locally
2. Test locally
3. Commit to GitHub
4. Push to main branch
5. Wait for auto-deployment (~2-5 minutes)
6. Test production site

**Pros:**
- ✅ Always online
- ✅ Easy to share
- ✅ Auto-deploys from GitHub
- ✅ Production environment

**Cons:**
- ❌ Slower feedback loop
- ❌ Need to redeploy for every change
- ❌ Harder to debug

## Database Comparison

### Local MySQL

**Connection:**
```env
DB_HOST=localhost
DB_PORT=3306
DB_USER=root
DB_PASSWORD=your-password
```

**Access:**
- MySQL Workbench
- Command line: `mysql -u root -p`
- phpMyAdmin

**Pros:**
- ✅ Full control
- ✅ Fast queries
- ✅ Easy to reset/test
- ✅ Free

**Cons:**
- ❌ Data only on your machine
- ❌ Not accessible from internet
- ❌ No automatic backups

---

### Railway MySQL

**Connection:**
```env
DB_HOST=containers-us-west-123.railway.app
DB_PORT=7896
DB_USER=root
DB_PASSWORD=railway-generated-password
```

**Access:**
- Railway dashboard
- MySQL client with public URL
- TablePlus, DBeaver, etc.

**Pros:**
- ✅ Accessible from anywhere
- ✅ Automatic backups
- ✅ Scalable
- ✅ Always available

**Cons:**
- ❌ Slower than local (network latency)
- ❌ Costs money (Railway: $5/mo free credit)
- ❌ Need internet connection

## Cost Comparison

### Local Development
- **Total: $0/month**
  - Frontend: Free (localhost)
  - Backend: Free (localhost)
  - Database: Free (local MySQL)
  - Stripe: Free (test mode)

---

### Production Deployment
- **Total: $0-5/month**
  - **Vercel (Frontend):** $0 (free tier)
    - 100 GB bandwidth
    - Unlimited deployments
    - Custom domain (optional)

  - **Railway (Backend + Database):** $5/mo free credit
    - Enough for demo/low traffic
    - ~500 hours uptime
    - 1 GB RAM

  - **Stripe:** $0 (test mode)
    - Test transactions free
    - No processing fees in test mode

## Migration Path

### From Local to Production

**Step 1: Ensure Local Works**
- [ ] App runs locally without errors
- [ ] Can register/login
- [ ] Can upload receipts
- [ ] Stripe subscription works
- [ ] Webhooks work with Stripe CLI

**Step 2: Prepare Code**
- [ ] Use environment variables (not hardcoded URLs)
- [ ] Add `.env` to `.gitignore`
- [ ] Test build: `npm run build`
- [ ] Commit all changes to GitHub

**Step 3: Deploy**
- [ ] Deploy backend to Railway
- [ ] Set up MySQL database
- [ ] Run migrations
- [ ] Deploy frontend to Vercel
- [ ] Configure Stripe webhooks
- [ ] Update environment variables

**Step 4: Test Production**
- [ ] Visit production URL
- [ ] Test all features
- [ ] Verify webhooks work
- [ ] Make test subscription
- [ ] Confirm database updates

**Step 5: Maintain Both**
- Local: For development
- Production: For demos/portfolio
